# OH MY BABY — إصلاحات لوحة Admin وسجل التدقيق وإدخال المنتجات

## تثبيت آمن (Windows / PowerShell)
1. خذ نسخة احتياطية من المشروع وقاعدة البيانات.
2. فك ضغط هذا الأرشيف في مجلد مؤقت.
3. افتح PowerShell داخل مجلد `website` نفسه الذي يحتوي على `artisan` و`resources`.
4. شغّل سكربت التثبيت من مكان فك الضغط، مثلًا:
   `& "C:\path\to\patch\INSTALL_PATCH.ps1"`
5. السكربت يبحث عن الملفات الثلاثة داخل `resources/js` ويتأكد أن لكل ملف نتيجة واحدة قبل نسخ أي تعديل. إذا وجد أكثر أو أقل من نسخة، يتوقف بدل تعديل ملف غير صحيح. تُحفظ النسخ الأصلية في مجلد `.omb-backup-*`.
6. نفّذ `npm run build` ثم افتح الموقع بتحديث قوي للصفحة (Ctrl+F5). إذا كان التطبيق منشورًا على خادم، يجب نشر ملفات البناء بالطريقة المعتادة للمشروع.

## التعديلات
- تحسين تنسيق مساحة لوحة Admin لتقترب من لوحة Owner، مع عدم تعديل منطق الصلاحيات عمدًا.
- تحويل مجموعة من أكواد سجل التدقيق إلى عناوين مفهومة بالعربية والإنجليزية، مع عرض مقروء احتياطي للأكواد غير المعروفة.
- جعل الاسم والوصف العربيين كافيين لإكمال نموذج المنتج، مع الحفاظ على توافق الحقول الإنجليزية القديمة.

## ملاحظة مهمة عن الترجمة
هذا التعديل لا يضيف ترجمة آلية حقيقية إلى الإنجليزية؛ لا يظهر في نسخة المشروع التي جرى فحصها مزوّد ترجمة مُعدّ. إدخال النص العربي وحده لا يمكن أن ينتج ترجمة إنجليزية موثوقة دون خدمة ترجمة أو آلية متفق عليها. لا يُنصح باعتبار النص العربي الموجود في الحقل الإنجليزي ترجمة فعلية.

## التحقق
الملف المصدر المتاح عبارة عن أرشيف يضم الملفات بأسماء مسطحة، وليس نسخة مشروع كاملة قابلة للتشغيل في هذه البيئة. لذلك لم أتمكن من تشغيل `npm run build` على نسخة المشروع الفعلية أو تأكيد السلوك داخل المتصفح هنا. بعد التثبيت شغّل البناء واختبر:
- لوحة Admin مقابل Owner مع حسابات بصلاحيات مختلفة.
- سجل التدقيق باللغتين، بما في ذلك إجراء غير معروف.
- إنشاء منتج باسم ووصف عربيين، والتحقق من بقاء المنتجات القديمة والحقول السابقة سليمة.
